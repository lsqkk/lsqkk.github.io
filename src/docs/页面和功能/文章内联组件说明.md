# 文章内联组件

Markdown 可以包含以下 HTML 约定，`astro.config.mjs` 的 rehype 插件会在构建时转换。样式使用 `post.css` 中的表面、描边与排版规则，主题来自共享令牌。

## 引用入口

~~~html
<div id="card" title="标题" intro="简介" tag="标签" description="补充说明"
     href="/posts/about" image="/assets/img/logo_blue.png"></div>
~~~

`id="card"` 触发 `rehypePostCard`。标题可省略，简介支持 `intro / summary`，链接支持 `href / link`，图片支持 `image / img / src`。有链接时整块是链接，否则为静态内容。

引用入口采用图片与正文并列布局，手机按实际空间调整。表面为实色、小圆角与细描边；悬停和焦点提供反馈，不使用大幅抬升来表示可点击。

## 文件预览

~~~html
<filepreview src="/assets/pdf/我们都很棒.pdf" title="钢琴谱" size="96KB"></filepreview>
~~~

`src` 为文件地址，`title` 和 `size` 为可选显示文本。PDF 通过折叠区的 iframe 预览，首次展开才加载；其他文件提供下载与不支持内嵌预览的说明。

文件信息头支持点击及 Enter / Space，下载操作独立。源码附件放在 `assets/` 对应目录，由同步脚本发布；不要手工放进生成目录。使用第三方文件时保留来源与授权说明。

## 提示块

~~~html
<note type="tip" title="阅读提示">
  <p>这里可以写补充说明。</p>
</note>
~~~

`rehypeNote` 支持 `info`、`warning`、`tip`、`danger`，未知类型回退到 info。标题可省略，由类型提供默认名称。提示用于辅助说明，不替代正文标题结构。

## Mermaid 与脚注

语言为 `mermaid` 的代码块由 `rehypeMermaid` 转换为图表容器，客户端按需渲染。图表仍需考虑失败时的可读说明与移动端宽度。

脚注采用 Markdown `[^id]` 语法，详见[脚注与参考文献](文章脚注与参考文献说明.md)。

## 实现与维护

实际注册顺序为 `rehypeRaw`、`rehypePostCard`、`rehypeFilePreview`、`rehypeMermaid`、`rehypeNote`。`rehypeRaw` 先把原始 HTML 转成 HAST 节点，后续插件再替换约定结构。

引用与提示样式在 `post.css`；文件预览交互由插件生成的脚本负责。修改时使用真实文章进行生产构建和预览，核对链接、下载、键盘、深浅主题和窄屏，不只检查示例语法。
