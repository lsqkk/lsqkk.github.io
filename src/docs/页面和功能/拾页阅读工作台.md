# 拾页 · 阅读工作台

入口：/desk/。首页、文章列表、文章页与功能导航均提供入口。沿用站点实色表面、分隔线、克制蓝色与深浅主题，不引入第三方服务或依赖。

## 为谁解决什么问题

- 时间有限的访客：设定 3–35 分钟预算，再按兴趣挑选一篇读得完的文章。每篇时长独立按 400 字/分钟估算，图表、外链和动手实践不计入。
- 不知道从哪里开始的访客：三条编辑选择的跨文章路线，为每一步写明连接理由。路线数据在 src/config/reading-paths.json，不用关键词冒充内容理解。
- 想下次接着看的人：待读清单支持排序、已读切换与跨页面同步。首页会出现下一篇待读入口。
- 想留下一点收获的人：正文选中文字后，在原有划线菜单点击“摘录到拾页”。保留原文、文章链接和可用的章节锚点；在工作台补写私人想法。文章开头另有摘录按钮，支持超出划线讨论长度限制的选择。

路线涉及的文章，在正文之后显示当前路线和其他文章入口；无须从工作台进入，搜索访客也能发现联系。

## 数据与边界

- 只使用 localStorage 的 quark.reading-desk.v1，schema 为 {version:1,queue:[],clips:[]}。不读取账号，不把清单、原文摘录或想法发送给服务端；站点其他公共脚本保持既有行为。
- 待读最多 200 篇，摘录最多 500 条，原文/想法各最多 4000 字符。备份导入最大 1 MB。
- 使用原生 storage 事件同步同源标签页；单页通过 quark:desk-updated 通知。
- 保存失败会明确提示；损坏的旧存储不会被一次写入静默覆盖。摘录移除提供撤销。
- JSON 备份导入按文章地址、摘录地址+原文去重合并，保留当前已有内容。只接受本站 /posts/ 下的地址；动态文本通过 textContent 渲染。
- Markdown 阅读手记包含已读状态、原文块引用、私人想法与完整来源 URL；JSON 用于跨设备或浏览器备份。清除浏览器数据会移除未备份内容。
- 页面不是全文离线缓存。JavaScript 不可用时，编辑选择的路线链接仍由 Astro 输出。

## 源文件

- 页面：src/pages/desk/index/index.astro，沿用 GitHub Pages 的目录路由输出约定。
- 数据模型：assets/js/reading-desk-store.mjs，浏览器和 Node 单测共用。
- 交互：reading-desk.js、post-reading-desk.js、reading-desk-entry.js。
- 组件：ReadingDeskEntry.astro、ReadingPathContext.astro。
- 样式：assets/css/reading-desk.css，消费既有 tokens。
- 原有 post-annotation.js 的选择菜单派发 quark:clip-selection 事件，本地摘录不等待 Firebase。

首页内容开关在 src/config/json/index_config.json。时钟、IP 问候、随机问候、打字机与在线预览默认关闭；不可见组件不启动对应的轮询或数据请求。

## 验证

- npm run test:desk：存储、合并、失败保护、URL 校验与 Markdown 来源。
- npm run test:ui:desk：320/390/768/1100/1440 深浅主题几何检查，真实摘录、清单、持久化、备份、错误反馈、导出与文本安全渲染。
- npm run build：生产静态构建、站点地图与搜索索引校验。
- 既有 npm run test:ui:polish、npm run test:ui、npm run test:sitemap 验证原有页面。
- 浏览器验证会屏蔽第三方请求，以检验阅读工作台的本地能力；不代表对登录、云端评论及远端工具的验收。截图在忽略目录 test-results/reading-desk。
