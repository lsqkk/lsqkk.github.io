# 权衡 · 决策实验室

入口 `/tool/decision/`，由工具箱目录收录，随构建进入 sitemap 与站内搜索。页面使用现有表面和主题令牌，不依赖额外包、API 或账号。

## 比较与偏好沙盘

支持 2–5 个方案、1–6 个因素。每个因素设置 0–10 的相对重要程度，为每个方案填写 0–10、以 0.5 递增的满意度评分。费用和耗时等成本型因素也转换为满意度，高分始终表示更满意。相对重要程度除以总和得到实际占比；贡献分相加得到总分。

空白评分保存为 `null`，不冒充 0；有任何未填或无效评分、或所有重要程度均为 0 时暂停排名。严格并列使用浮点容差，不用显示时四舍五入后的值判断。条形各段表示因素贡献，读屏标签同时给出数值。移动端评分按因素分组；编辑表格时出现当前结论与结果跳转条，结果区进入视口后收起。

沙盘只改变试验情景，不修改草稿：将一个因素的绝对占比设为 0–100%，其余因素按原重要程度比例分配剩余占比。如果其他因素均为零，则等分剩余占比并明确说明。只有一个因素时不显示沙盘。

每个方案的分数随所选占比线性变化，模型求所有两两直线的交点，再用每个区间的中点确定领先组，合并相邻同组区间。它不靠随机抽样推测稳定性。图表同时使用颜色和线型，并提供领先区间的文字表示。初始化优先选择有更多领先切换的因素，使示例能直接展示取舍。

## 本地草稿与备份

- localStorage 键为 `quark.decision.v1`。首次示例不直接写入，修改时保存一份当前草稿；清理浏览器数据会丢失未备份内容。
- schema 为 `{version:1,title,options:[{id,name}],criteria:[{id,name,weight,scores:{[optionId]:number|null}}]}`。导入重建白名单字段，检查版本、个数、名称长度、重复标识、有限数值与评分范围，拒绝不完整数据；文件最大 100 KB。
- JSON 导出用于继续编辑，Markdown 导出包含因素、占比、评分和当前结果。原生下载文件名去除系统保留字符。
- 导入、打开示例和新建空白比较前均显示替换对话框，可 Esc 取消并恢复焦点。提供一步撤销，移除方案或因素后也能恢复。
- 损坏草稿不会被示例静默覆盖；保存失败有持续状态提示，可导出本页内容。其他标签页修改或清除草稿后，本页暂停保存，让用户先备份再主动载入最新数据，避免互相覆盖。
- 交互与存储模块不发送草稿。页面的站点导航等公共脚本保留现有行为。
- 无 JavaScript 时显示说明与工具箱返回链接。

## 维护与验证

- 路由：`src/pages/tool/decision/index/index.astro`。
- 页面脚本、样式、示例与计算模型：`assets/pages/tool/decision/`。
- `npm run test:decision`：决策模型与随行架存储单测。
- `npm run test:ui:decision`：示例、缺失评分、并列、零权重、无效值、撤销、持久化、备份、文本注入防护、存储损坏、多标签页冲突、键盘及响应式布局。
- 先运行 `npm run build`，再启动生产预览；浏览器测试使用已有 Playwright 与 Chromium，并隔离外部服务。截图在忽略目录 `test-results/decision-pocket/`。

评分和因素的选择由访客决定；加权结果表示输入偏好下的比较，不表示对现实结果的预测。
