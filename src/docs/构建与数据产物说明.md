# 构建与数据产物

在仓库根目录执行 `npm ci` 安装锁定依赖，使用 `npm run build` 进行正式构建。

## 构建链路

| 阶段 | 源码 | 作用 |
| --- | --- | --- |
| `prebuild` | `scripts/generate-posts-json.mjs` | 扫描 `posts/**/*.md`，生成文章元数据并复用已有封面；缺封面时尝试远端图片地址，失败时保留空值 |
| `prebuild` | `scripts/generate-rss.mjs` | 根据元数据及正文生成 RSS |
| `prebuild` | `scripts/sync-public.mjs` | 同步静态资源、配置、订阅文件、字体 CSS 与 API 占位符 |
| `prebuild` | `scripts/extract-fa-icons.mjs` | 提取实际使用的 Font Awesome SVG，生成脚本、JSON 和本地图标 CSS |
| `build` | `astro.config.mjs` | 生成页面、文章、兼容跳转、sitemap 与搜索索引，替换 API 占位符 |
| 构建集成 | `scripts/sitemap-compat.mjs` / `scripts/optimize-static.mjs` | 保留 sitemap 兼容地址，压缩公开 CSS/JS、展开公共 CSS import |
| `postbuild` | `scripts/verify-dist.mjs` | 校验 sitemap 索引及分片、robots、旧别名、页面索引，以及文章 canonical、分享地址与 JSON-LD |

`quark build` 封装同一构建流程，`quark build --mode artifact` 额外将产物复制到 `.quark-artifact/`。

## 数据来源

| 源码 | 生成或使用位置 |
| --- | --- |
| `posts/**/*.md` | Astro 内容集合、文章元数据与全文搜索 |
| `posts/posts.json` | 首页、文章列表、封面、阅读工作台；同步为 `public/json/posts.json` |
| `posts/rss.xml` | 复制到公开站点的 `/posts/rss.xml` |
| `assets/data/dt.json` | 首页动态、动态列表、详情与动态搜索 |
| `assets/data/log.json` | 首页和日志页；由 `quark updatelog` 根据 Git 提交整理 |
| `assets/pages/tool/tool.json` | 工具目录 |
| `assets/pages/games/game.json` | 游戏目录 |
| `assets/pages/a/projects.json` | 实验室目录 |
| `assets/pages/blog/functions.json` | 功能导航 |
| `src/config/retired-pages.json` | 下线路径的 noindex 兼容跳转及搜索排除 |
| `src/config/reading-paths.json` | 阅读路线与文章关联 |

`public/` 来自 `assets/`、`src/config/json/` 和部分根目录文件。`assets/` 是资源源目录；`public/` 不是另一份手工维护的资源目录。Python、Markdown、缓存及工具用 package.json 等文件按同步脚本规则排除。

## 字体与图标

`font.json` 描述字库注册来源，构建生成 `public/assets/css/font-config.css`。生成 CSS 的初始栈使用系统回退字体；导航加载 `user-preferences.js` 后应用站点默认的霞鹜文楷或用户保存的字体选择。不要将生成 CSS 的初始栈误当作最终阅读设置。

图标提取产出 `public/assets/js/fa-icons.js`、`fa-icons.json` 和 `public/assets/css/fa-local.css`。页面优先使用这些本地资源，不因一个图标额外载入整套远程图标字体。

## API 地址与站点身份

`src/config/json/api.json` 的 `apiBase` 通过 `__API_BASE__` 注入同步资源和最终 HTML；开发环境由 Vite 插件提供相同替换。

站点 URL 和身份还用于 `src/config/site.js`、`astro.config.mjs`、RSS 及维护工具，迁移时按[部署说明](迁移部署说明.md)一并核对。API 地址不是静态站点地址，服务端凭据不写入公开 JSON。

## 路由与索引

Astro 仍按 `build.format: "file"` 处理现有页面结构。发布前，`scripts/directory-pages.mjs` 将平铺页面整理为目录下的 `index.html`，并保留 GitHub Pages 使用的根级 `404.html`。发布后 `/settings` 会跳转到 `/settings/`，两种入口都可携带查询参数和锚点。旧的 `/settings.html` 等地址在 404 页按发布索引匹配并恢复。开发路由由 `buildDevRedirects` 适配，验收以生产产物为准。

`@astrojs/sitemap` 生成 `sitemap-index.xml` 与分片；`sitemap.xml` 保留为同内容的索引别名。`robots.txt` 指向索引文件。目录入口和下线路径由 sitemap 兼容逻辑统一处理。

构建后 `dist/json/site-pages.json` 结合 sitemap、页面标题与目录数据生成。搜索页还输出文章及动态的全文数据。新增路由后要核对标题、目录入口、搜索结果和 sitemap；不要只检查文件是否存在。

## 预览与缓存

~~~sh
npm run build
npm run preview -- --host 127.0.0.1
~~~

预览地址以终端输出为准。首次开发或修改静态源资源后执行同步；`npm run dev` 的模板热更新不等于所有 `assets/` 文件都会自动复制。

Service Worker 对脚本、样式、JSON、MJS 使用 stale-while-revalidate，对图片和字体缓存优先，对导航网络优先。调试旧资源时应检查浏览器缓存与 Service Worker，而不是手改 `dist/`。

## 修改规则

只编辑源文件。`public/`、`dist/`、`.quark-artifact/`、`posts/posts.json` 和 `posts/rss.xml` 都是生成产物。`docs/demo/` 是 README 截图资料，不放进 `assets/`，因此不会增加网站公开资源的体积。

构建变更至少通过 `npm run build`、`npm run test:sitemap` 和 `npm run check:docs`；界面变更再选择相应 UI 回归。功能测试、截图、临时基线放进忽略目录 `test-results/`。
