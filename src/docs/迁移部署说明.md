# 迁移与部署

网站由静态页面和独立在线服务组成。可以只运行内容与本地工具；登录、评论、协同、上传和实时房间需要相应服务配置。

## 本地准备

使用 Node.js 22.12+ 与 npm，锁定依赖在 `package-lock.json`：

~~~sh
npm ci
npm run build
npm run preview
~~~

按终端给出的地址查看生产产物。`npm run dev` 用于模板开发，首次运行先准备 `public/`；详见[构建链路](构建与数据产物说明.md)。

需要 Quark CLI 时再创建 Python 虚拟环境、安装 `requirements.txt` 并执行 `python -m pip install -e .`。`quark serve` 默认构建后预览，`--dev` 切换为开发服务器，`quark web` 提供本地配置面板。

## 替换站点身份

| 位置 | 核对内容 |
| --- | --- |
| `src/config/json/nav.json` | 标题、logo、导航、OAuth client_id / redirect_uri、Turnstile site key |
| `src/config/json/index.json` | 昵称、联系方式、外链、首页内容 |
| `src/config/json/index_config.json` | 首页展示开关 |
| `src/config/json/friends.json`、`manifest.json`、`notices.json` | 友链、PWA 与站点通知日程 |
| `src/config/site.js` | 站点 URL、作者与派生配置 |
| `astro.config.mjs` | `site` 及 sitemap 的站点地址 |
| `src/config/json/api.json` | API 地址；RSS 的站点覆盖字段 `siteUrl`（如使用） |
| `robots.txt` | sitemap 的完整站点地址 |
| `scripts/generate-rss.mjs` 与 `quark/` 维护命令 | 回退站点地址、仓库链接等身份引用 |
| `assets/img/` | logo、头像等实际使用素材；默认站点背景为实色 |
| `posts/`、`assets/data/` 与页面目录 JSON | 自己的内容与功能入口 |

不要将原站作者文章、身份资料和素材视为模板占位内容直接署上自己的名字。代码、文章与第三方资源的许可分别见 [LICENSE](../../LICENSE) 和[版权说明](../../posts/copyright.md)。

本站使用根路径 `/assets/...`；迁移到 `username.github.io/repository/` 子路径需要额外调整根路径引用，不能只改 Astro 的 `base` 就视为完成。

## 静态站点：GitHub Pages

`.github/workflows/deploy-pages.yml` 监听 `main` 分支推送及手动运行，使用 Node.js 22、`npm ci`、`npm run build`，上传 `dist/` 后通过 Pages 发布。

在仓库的 Pages 设置中选择 GitHub Actions。自定义域名和 DNS 按实际托管设置配置。发布后检查首页、文章、目录、搜索、RSS、sitemap 以及一个旧路径的兼容跳转。

## 在线 API：Vercel

根目录 `api/*.js` 是 Vercel Serverless 函数。`vercel.json` 保持 `framework: null`、跳过 Astro 静态构建，`outputDirectory` 为 `"."`。静态页面由 Pages 发布，Vercel 在此承担 API。

部署 API 后，将 `src/config/json/api.json` 的 `apiBase` 改成完整 HTTPS 地址，例如 `https://api.example.com`，再重新构建静态站点。完整路由和参数见 [API 索引](API/README.md)。

## 服务配置

仅配置启用功能对应的变量，不在仓库或截图中保存真实凭据。变量名参考根目录的 [.env.example](../../.env.example)，它不会自动为 Vercel 或本地 Astro 配置在线服务。

| 功能 | 服务端环境变量或公开配置 |
| --- | --- |
| Firebase 浏览器配置 | `FIREBASE_API_KEY`、`FIREBASE_AUTH_DOMAIN`、`FIREBASE_DATABASE_URL`、`FIREBASE_PROJECT_ID`、`FIREBASE_STORAGE_BUCKET`、`FIREBASE_MESSAGING_SENDER_ID`、`FIREBASE_APP_ID`；`FIREBASE_MEASUREMENT_ID` 可选 |
| RTDB Admin 代理 | `FIREBASE_SERVICE_ACCOUNT` 或 `FIREBASE_SERVICE_ACCOUNT_JSON`，以及 `FIREBASE_DATABASE_URL` |
| GitHub OAuth | `GITHUB_CLIENT_ID`、`GITHUB_CLIENT_SECRET`；前端 `nav.json` 中配置自己的授权地址 |
| Turnstile | `TURNSTILE_SECRET_KEY`；前端 `nav.json` 配置自己的 site key |
| 管理员会话 | `ADMIN_PASSWORD_HASH`、`ADMIN_SESSION_SECRET` |
| 邮件验证码 | `RESEND_API_KEY`、`RESEND_FROM`、`EMAIL_TOKEN_SECRET` |
| R2 上传 | `R2_ACCESS_KEY_ID`、`R2_SECRET_ACCESS_KEY`、`R2_ENDPOINT`、`R2_BUCKET`、`R2_PUBLIC_BASE_URL` |
| 页面可读配置注入 | `TIANDITU_KEY`、`GITHUB_API_KEY`；接口还保留 `OPENWEATHER_API_KEY` 映射，但天气页不在当前目录中 |
| AI、音视频与其他实验 | 按具体页面配置模型端点、客户端凭据、Agora 或其他服务；不能仅凭 API 构建成功确认其可用 |

浏览器可读的配置不是服务端秘密：经 `/api/keys` 或 `/api/firebase-config` 返回的值能够在浏览器中查看。需要保密的令牌应留在服务端；Firebase 的访问控制依靠数据库规则，而不是隐藏其前端配置。

### QuarkBot 站点免费 AI

QuarkBot 的默认模式通过现有 Vercel API 项目调用 AI Gateway 的 `alibaba/qwen3.5-flash`，访客打开面板即可发送消息。在 Vercel 项目启用 [OIDC Federation](https://vercel.com/docs/oidc)，函数通过平台提供的 OIDC 令牌调用网关。保持 AI Gateway 在免费档，免费档团队每月有 5 美元共享额度。 [AI Gateway 定价](https://vercel.com/docs/ai-gateway/pricing)

QuarkBot 全站每天最多转发 120 次模型请求。访客同一 IPv4 地址或 IPv6 /64 网段每天 5 次，验证登录后按账号每天 40 次。360° 全景云端上传为访客每天 5 张、验证登录后每天 25 张，以签发上传链接计数。本地预览和校准无需额度。两个服务均在北京时间 00:00 刷新。QuarkBot 的工具调用可能产生多次模型请求。

登录权益由 GitHub 授权回调或已绑定邮箱的验证码登录发放。老会话和账号密码登录可通过权益提示重新验证。服务端复用 RTDB Admin 配置。`quarkbot_free_quota`、`xjtu360_upload_quota`、`quark_email_challenges` 只供 Admin SDK 访问，请确认 Firebase 规则没有在上层向客户端授予这些路径的读写权限。

部署后从站点实际来源打开 QuarkBot，发送一条短消息并确认流式回复，再切换到「自定义 API」验证已保存的共享连接。QAI WebUI 和网页 Quark 终端继续直接使用原有连接。

## 来源、规则与上传权限

来源配置集中在 `api/_cors.js`，不同接口使用 `resolveOrigin` 或 `allowOrigin`。核对实际站点域名、开发地址及端口，不能只改 `apiBase`。默认开发预览端口与来源列表不一定一致，动态调试时需要显式配置。

Firebase RTDB 顶层路径及读写规则需要在自己的项目中设置；新增游戏命名空间不会自动开放。源码中的路径白名单也不替代 RTDB 规则。R2 需要配置浏览器 PUT 上传的 CORS，并确认生成的公开地址可访问。

管理员接口使用 `/api/admin?action=auth` 和 `/api/admin?action=verify`；邮箱接口使用 `/api/email?action=send` 和 `/api/email?action=verify`。不要配置不存在的独立函数文件。

## 验收

1. 静态检查：`npm run check:syntax`、`npm run check:docs`、适用单测和 `npm run build`。
2. 本地页面：生产预览下检查深浅主题、手机宽度、文章、搜索、目录和下载。
3. 服务集成：在自己配置的环境中验证登录、邮件、评论、数据库规则、上传及需要保留的实时产品。
4. 发布确认：确认 Pages 工作流完成、实际地址返回新页面；API 部署状态独立核对。
5. 数据备份：浏览器本地清单、摘录和工具状态不随 Git 部署迁移。

常见问题：资源仍旧时检查同步与 Service Worker；API 403 时核对来源；Firebase 权限错误时核对规则和路径；刷新深层目录失败时核对实际生成路径。`npm run typecheck` 的历史诊断按[类型说明](TypeScript规范说明.md)处理，不应被写成“全仓类型检查通过”。
