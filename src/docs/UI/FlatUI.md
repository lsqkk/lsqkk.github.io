# 结构与排版

布局优先使用有语义的分区、留白和分隔线。表面颜色及描边见[表面系统](SurfaceSystem.md)，总体原则见[设计原则](UIDesignPrinciples.md)。

## 结构层级

一个页面外壳承载标题、说明和主要内容，区域之间用间距或细线分开。列表行以文字、元信息与必要操作组织；不要在外层面板中继续给每一行套独立面板。

卡片适用于多个独立目的地并列的目录。每张卡片最多一个表面，名称和用途是主信息，标签作为补充。目录分类由区块标题和分类导航表达。

## 不同页面

| 场景 | 结构 |
| --- | --- |
| 首页 | 作者介绍、主要内容、辅助侧栏；手机改为单列 |
| 文章 | 标题与元信息、阅读操作、正文、文章关联、评论；桌面目录有独立网格列 |
| 工具 / 游戏 / 实验室目录 | 共用目录布局，先说明用途，再提供筛选和入口 |
| 表单工具 | 输入、主操作、结果；结果可以复制、下载或继续处理 |
| 实时房间 | 房间状态与身份、当前任务、操作区、必要的历史和聊天 |
| 阅读工作台 | 时间与兴趣选读、待读、主题路线、私人摘录与导出 |

宽度以现有布局为基准：阅读正文约 58ch–800px，目录和首页约 1200–1400px。工具工作区可更宽，但不能牺牲小屏可用性。

## 信息层级

标题、正文、说明、日期和辅助操作通过字号、字重与位置区分。日期与数值可以使用等宽数字；正文不要压缩成密集的小号标签。

移动端保留内容边线和足够左右留白。长标题、文件名、评论和 URL 应能换行；代码、表格等确实需要横向空间的内容使用局部滚动容器。

## 样式实现

使用页面前缀，如 `desk-*`、`catalog-*`、`post-*`。避免裸写 `header`、`button`、`.title` 等影响共享元素的规则。新增规则先核对源文件末尾的覆盖层，避免不断叠加互相冲突的兼容样式。

悬停可以改变文本、底色或边线，不应让整个目录列表跳动。小屏触控范围和可见尺寸分别设计；减少动态效果时仍保留完整状态反馈。
