# 界面设计原则

界面服务于阅读、发现内容和完成工具任务。使用实色表面、留白、细分隔线和克制的强调色，主要内容直接进入页面结构。

## 视觉与排版

- 颜色、圆角、阴影、间距和动效时长以 `assets/css/tokens.css` 为准。深浅主题共享同一组语义变量。
- 页面底色用 `--page-bg`，内容表面用 `--surface*`，描边用 `--line*`；蓝色用于主要交互，其他语义色按状态使用。
- 圆角采用 2–10px 的令牌；头像、状态圆点等可用圆形。内容层级依靠排版和描边，不依赖模糊、重阴影或背景图。
- 默认阅读字体为霞鹜文楷，由 `user-preferences.js` 应用。用户可切换系统字体等选项；输入框继承站点字体，代码保留等宽字体。
- 标题有清晰层级；正文保持舒适行长。次要说明不得仅靠极低透明度区分。

## 页面结构

- 阅读页用正文主栏与独立目录；宽表格和代码块在自身区域滚动。
- 首页按作者介绍、阅读入口、文章和生活动态组织；辅助信息进入侧栏。
- 目录页使用 `CatalogLayout.astro` 的分类导航、搜索和内容网格；首屏入口由构建输出。
- 工具页按“输入—主操作—结果”组织；复杂编辑器可使用专门布局，避免把所有区域包装成多层面板。
- 具体约定见[结构与排版](FlatUI.md)、[表面令牌](SurfaceSystem.md)、[目录与工具](CatalogAndTools.md)、[阅读体验](ReadingExperience.md)。

## 交互与可访问性

使用语义化链接、按钮、标签与标题。图标按钮有可读名称，状态变化有明确反馈。交互至少考虑键盘、触屏和鼠标，保留焦点轮廓。

对话框、抽屉要处理 Esc、焦点进入与恢复；模态界面还要处理焦点循环和滚动锁。不能只加一个看起来像按钮的图标。原生 top layer 元素高于普通 z-index，可选自定义光标启用时也要能看见指针。

禁用 JavaScript 时，预渲染正文和目录链接仍可访问；依赖增强脚本的控件应隐藏或明确说明。加载、空结果、失败和成功属于不同状态，不能永久停留在骨架屏。

## 响应式与动态效果

以现有共享 gutter 为边界，考虑安全区域。320px 手机到宽屏都不能产生意外横向溢出；触控按钮优先保证约 44px 的实际操作范围，图标本身可更小。

动效只用于解释状态变化。正文不依赖淡入动画才能显示。尊重系统 `prefers-reduced-motion` 与站内减少动态效果设置，避免持续装饰动画。详见[动效](TransitionSystem.md)和[加载状态](SkeletonSystem.md)。

## 维护与验证

公共规则放在共享令牌和组件中，专属规则使用页面前缀；不要用泛化选择器覆盖导航、编辑器或其他工具。

继承表单字体时，选择器应限定到主内容容器，如 `.catalog-wrap input`，不要使用覆盖整个 body 的页面类。共享顶栏的语言和搜索字号由 nav.css 统一定义。桌面优先使用侧边空白容纳搜索、收藏与阅读操作；手机按需展开辅助区，避免这些内容把主要入口推到首屏之后。已有导航占位与页面顶部留白只能保留一套。

改动后按实际影响选择生产预览、深浅主题、移动布局、键盘操作和错误状态验证。UI 测试与截图在 `tests/ui/`、`test-results/`；不要把隔离外部服务的布局测试称作线上集成验收。
